# MCP and authenticated API sources resolve for real

**The `mcp` source kind resolves for real through the localhost proxy (stdio JSON-RPC), and an authenticated `api` source works via a proxy-side secret - credentials never reach the renderer or the lock**

Settled to the plan's recommendations. **D29-B (MCP config + resolution):** the proxy (`scripts/lwd-anthropic-proxy.js`) gained a `POST /mcp/resolve` route - `{ server, tool, args, field }` -> spawns/reuses the configured MCP server as a stdio child (newline-delimited JSON-RPC 2.0: `initialize` -> `notifications/initialized` -> `tools/call`), extracts `field` from the tool's text content, returns `{ value, raw }` with a 10s per-call timeout and structured `{ error }` on any failure. Servers are configured in an `mcp.json` (`{ servers: { <name>: { command, args } } }`) read from `LWD_MCP_CONFIG` or `./mcp.json`; a demo server (`scripts/lwd-demo-mcp-server.js`, serving rows from `scripts/lwd-demo-mcp-data.json`) + `scripts/lwd-demo-mcp.json` make the E2E reproducible offline. The bind syntax is the inline `bind:key@mcp:server.tool/field` (parsed by `parseMcpKey`); the service enumerates the doc's bind keys, resolves each `@mcp:` one through the proxy (web cannot spawn - the proxy does, so web + desktop share one path), and records the origin `server.tool#field` in the lock. A down/unknown server leaves the key unresolved so the binding flags stale and the document still renders - never an error toast. **D29-C (secrets):** secrets live proxy-side in `~/.abstract/secrets.json` (0600, `~/.abstract` 0700), keyed by name, set via a `node scripts/lwd-anthropic-proxy.js set-secret <name> <value>` CLI (which writes + exits, never starting the server). An `api` frontmatter source may name one as `<url> auth=<secret-name>`; the service strips the marker (the URL stays the clean identity/alias) and fetches THROUGH a new proxy `POST /proxy/fetch` route that injects `Authorization: Bearer <secret>` server-side - the renderer only ever sends the secret NAME, never its value. Non-auth `api` sources keep the direct `IRequestService` GET (byte-identical). Source-peek for an api/mcp value now shows the real response payload with the extracted field highlighted (escape-on-render safe: the payload is escaped, then the field name wrapped - never injected markup), closing the "provenance falls back to the CSV" gap; `ISourcePeek.payload` carries it. **Tier: our-surface + proxy script** (0 core patches). Verified: 4 new service unit tests (mcp resolves + records origin; a down server leaves it unresolved + doc renders; source-peek shows the mcp payload not a CSV; auth api resolves via the proxy and the secret VALUE never leaves it) driven through a stubbed proxy response, plus a live HTTP/stdio transcript (`docs/plans/29-verify/iter4-mcp-api-auth-transcript.md`): the demo server speaks JSON-RPC, `/mcp/resolve` returns `128,000` for `demo.query/total` and reuses the server, unknown server/tool return structured errors, and `/proxy/fetch` injects `Bearer <secret>` although the caller sent only the name. The packaged-desktop click-through (a doc bound to `bind:pipeline@mcp:demo.query/total` rendering the value in-app) reuses exactly this seam and is the one honest gap (chrome-devtools is browser-bound; matches decision 71).
