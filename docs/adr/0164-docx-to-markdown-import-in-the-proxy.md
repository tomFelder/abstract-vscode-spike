# Docx to Markdown import in the proxy

**docx -> Markdown import ships the doc 22 §2 pipeline: a `.docx` tree row becomes an "Import as Document" door; conversion runs in the node proxy (`POST /import/docx`) via pure-JS **mammoth** (docx -> semantic HTML), then a pure-TS HTML -> GFM step (`common/docxImport.ts`); the new `Name.md` is written beside the untouched original with `imported` provenance (`from` + `sourceHash` + kept/dropped) in the lock; embedded images lift to `assets/<doc>/`; the kept/dropped summary is a sticky plain-words notification card; `.doc`/password-protected/unparseable files stay refused**

Settled to doc 22 §2's stated recommendation on every open point. **mammoth over pandoc** (§2 implementation note): a pure-JS dependency the proxy loads at runtime keeps the pipeline dependency-light and bundle-free for beta; pandoc can slot behind the same flow later if tables/footnotes justify it. **HTML -> Markdown in pure TS** (not mammoth's experimental markdown writer, not turndown): the fidelity mapping the acceptance criteria bite on (GFM pipe tables, relative image refs, nested lists, escaping) lives in a DOM-free unit-tested module, so it is provable without a full build and carries no extra dependency. **Tracked changes import the final text and say so**; **tables are named display-only** until the #140 editing path; a "named and dropped" caveat (comments, tracked-change marks, footnotes, text boxes, headers/footers) appears **only when the source actually contained it** (detected from the raw docx parts via jszip) - never a fabricated caveat. **The original is never destroyed** (P6): import only ever writes a new `.md`. **Refusal over mangle** (plan 33 L8): a CFB/encrypted or corrupt file returns `ok:false` with a plain-words reason and the tree row is left untouched. The summary **card** ships as a sticky notification + durable lock provenance rather than an in-editor webview banner (the criterion is "a card is shown"; the heavier render-pipeline banner is a later polish). **Tier: our-surface + 1 npm dependency, 0 core patches.** Verified: `docxImport` unit suite (8 cases) + the pipeline exercised end-to-end against a real `.docx` through the live proxy (headings, nested lists, GFM table, 2 images, tracked-changes final text, comment detection) and all three refusal fixtures; artefacts in `docs/plans/40-verify/a1-import/`. Live in-workbench click of the tree door / notification card is NOT yet done (worktree unbuilt) - honestly recorded in the verify README.
