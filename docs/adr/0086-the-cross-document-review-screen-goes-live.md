# The cross-document review screen goes live

**Per-change Accept/Reject/Tweak + the sticky doc action bar (Accept All Here / Next / Accept All Remaining) all drive the EXISTING review engine; the screen, the doc-nav rail and the C6 Review rail re-sync from the shared model via `onDidChange`; reviewed docs carry the human title; an honest "All changes reviewed" end state. 0 core patches.**

Completes plan 24: the read-only C5 surface (decision #83) is now fully wired, reusing the same engine `reviewRailView.ts` consumes — no new approve/reject logic. **Per-change actions** (`reviewCard`, `screenRender.ts`): each card's Accept posts `reviewAccept`→`approve(id)`, Reject posts `reviewReject`→`reject(id)`, Tweak posts `reviewTweak`→`ScreenEditor._tweakChange(id)` which resolves the change's `docId` from the live `getAllPending()` set, opens that document (`IEditorService.openEditor`) and calls `focusChange(id)` — the plan-19 navigate-to-inline path, navigate-only (never approves). **Sticky doc action bar** (`reviewColumn`): `Accept All N Here` posts `reviewAcceptAllHere`→`approveAll(currentDocId)`; `Next: <doc>` posts `reviewNext`→advances `reviewCurrentDocId` to `nextPendingDocId(getAllPending(), currentDocId)` (reused the existing pure model helper; the label names the next changed doc; the button is omitted when only one doc still has changes); the topbar `Accept All Remaining (N)` posts `reviewAcceptAllRemaining`→`approveAllPending()`. **Live re-sync:** reuses the EXISTING `_inputDisposables` subscription to `livingDocs.onDidChange` → `_render` (registered in `setInput`); after any engine action the service fires `onDidChange`, `_render` recomputes `_reviewProjectState()` from the live pending set, so the centre cards, the rail counts/glyphs AND the C6 Review rail (a second consumer of the same model) all update together — no new event path, no new disposables. **Reviewed-set-with-title fix (from #83's gap):** the editor now tracks `reviewSeenDocs: Map<docId,title>` — every doc seen with a pending change this session records its `docTitle`; the new pure TDD'd `reviewedDocsFromSeen(seen, pendingDocIds)` (`livingDocsModel.ts`, 2 tests) derives the reviewed list (seen minus still-pending) carrying the HUMAN title, so the rail's check rows show e.g. "Access Control Policy", not the raw `file://…` URI. **End state:** when nothing is pending, `renderReviewProject` shows a calm centre state — the celebratory "All changes reviewed" (+ "Every proposed change across N documents has been actioned.") only when a review actually happened this session (`reviewedDocs.length > 0`), else an honest "Nothing waiting" idle. **Carry-over fix:** corrected the inverted `reviewCard` diff-order comment (code renders addition-then-removal; the comment said removal-then-newText). **Verified live** on `./living-docs-sample-isms` (throwaway :8082, 1440×900): Agents → "Run Across the Project" fanned out and settled to **4 real pending changes across 4 docs** (Access Control/MFA line 2, Acceptable Use/BYOD line 15, Vulnerability Management/remediation line 27, Change Management/emergency line 30);
