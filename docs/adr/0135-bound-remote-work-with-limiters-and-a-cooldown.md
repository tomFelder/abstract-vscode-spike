# Bound remote work with limiters and a cooldown

**A refresh/agent run bounds its remote work with two `Limiter`s (4 concurrent source fetches, 2 concurrent model calls) and a workspace-wide per-host cooldown (30 s), all reading an injectable `IClock`**

Settled to the plan's D30-A recommendation. Bounded concurrency uses `vs/base/common/async`'s `Limiter` (not hand-rolled): `_sourceLimiter = new Limiter(4)` gates every REMOTE (api/mcp) source fetch, `_modelLimiter = new Limiter(2)` gates the buffered `_callModel` (graders/impact), and both are service-owned disposables. Local file reads are NOT limited - they are cheap and hit the per-pass read cache. The per-refresh document derivation kicks off concurrently (`Promise.all`) and the bound concurrency lives ONE level down inside each derive (the fetch/model limiters); gating at the document level too would deadlock, because a document holding a limiter slot then awaits a nested fetch on the same limiter. A per-host cooldown map (`_hostCooldown`, keyed by URL host, workspace-wide so it survives across passes) suppresses an identical remote fetch within `SOURCE_COOLDOWN_MS = 30_000` - unauthenticated GitHub is 60 req/h/IP (doc 04), so a per-source cooldown is correctness, not polish; a suppressed fetch reuses an empty resolution (its bind keys keep their last-known lock values, freshness unchanged). The cooldown reads an injectable `IClock` (the same seam the orchestrator uses; a `setClock` test hook installs a fake clock rather than adding a DI constructor param, which would break the service's `registerSingleton` signature) so the 30 s window is advanced deterministically in tests, never with wall-clock waits. The agent-run document loop stays SEQUENTIAL to preserve the plan-27 per-run Stop contract (a Stop leaves the remaining documents unprocessed and honestly skipped, in order); only the inside of a derive parallelises. **Deviation (logged):** the plan-27 `CancellationToken` was already threaded through `runAgent`/`_runAgent` (plan 27 landed), so no new token wiring was needed for track 2. **Tier: our-surface, 0 core patches** (`livingDocsService.ts` only for the scheduler). Verified: `perfScale.test.ts` asserts ≤ 4 concurrent source fetches (deferred-fetch peak), the model limiter caps at 2, a rejecting fetch fails only its document (others derive), and the cooldown suppresses then re-admits across a fake-clock 30 s window - all MEASURED, numbers in `docs/plans/30-verify/notes.md`. Live in-app verification: see `docs/plans/30-verify/README.md` (the derivation path is deterministic and model-independent; the model backend remains unreachable - no credits).
