# Tweak is amend before approve

**Tweak is amend-before-approve through the ONE approve path - a service `amendChange` that mutates the pending proposal, plus an in-place editor on both the inline widget and the cross-doc card**

Settled to the plan's recommendations. **D31-A (interaction shape):** a pencil `Edit` beside Approve/Reject opens an in-place editor over the *proposed* text - a contenteditable inside the widget's host-provided DOM (never the PM document, so the doc stays read-only until approval and there is no undo-stack coupling) - with `Save & Approve` / `Cancel`. The cross-document card gets the same affordance INSIDE the card (Edit → contenteditable → Save & Approve / Cancel), and the plan-24 navigate-to-the-doc behaviour is kept as a secondary `Open in document ↗` link. The affordance HIDES for a `figure` proposal (figures come from sources; not hand-editable). **D31-B (amend semantics):** a new `amendChange(changeId, newText)` on `ILivingDocsService` replaces the pending change's `newText`, flags it `tweaked`, and fires `onDidChange` so every surface re-renders the amended proposal as still-pending; the subsequent `approve` records the audit `via: 'tweaked'` (added to the `IAuditEntry.via` union) so the trail shows the human modified the agent's words - a trust signal. No parallel apply route: `Save & Approve` calls `amendChange` then the existing `approve(changeId)`, and the amended text lands through the same serialisation approve already uses. **Tier: our-surface, 0 core patches** (`livingDocsService.ts`, `livingDocRender.ts`, `screenRender.ts`, the two editor hosts). Verified: 3 service unit tests (amend→approve applies the human text + audits `via: tweaked`; amend→reject discards cleanly, prose untouched, nothing approved; amend no-ops on an unknown id / empty / no-op amendment). The required live E2E on `:8080` (chat → propose → Tweak → approve) was blocked by the unreachable model backend - a proposal needs a real model call and both backends are unavailable (Anthropic "credit balance too low", OpenRouter key unset), so the pending Tweak editor has nothing to render; the app itself builds and runs, and the PR #100 validator served it live on :8080 with Home/editor/rails rendering (esbuild was a resolvable node_modules layout quirk, symlinked from build/node_modules into root, not unbuildable code). The blocker detail is at `docs/plans/31-verify/README.md`. No live pass was fabricated. Figure-hides-Edit is enforced by the widget/card gate on `kind !== 'figure'` (the decoration carries `kind`, tested).
