# Refresh is incremental and source-scoped

**`refreshFromSources(resource?)` is incremental and source-scoped: a cheap freshness hash-check picks the affected documents, and one per-pass cache reads each shared source exactly once**

Settled to the plan's track-1 recommendation (iteration 2). The project-wide `refreshFromSources()` no longer sweeps every discovered document: it loads the candidate states, recomputes freshness CONCURRENTLY (the cheap hash-check already implemented in `_recomputeFreshness`), and re-derives ONLY the documents that are (a) explicitly targeted, (b) actually stale (a source hash moved), (c) never-synced (a bind key with no lock entry), or (d) still showing figures that differ from the lock's resolved values - the last preserves the pre-plan-30 "a manual Refresh always reconciles the visible cache" behaviour, so byte-identical small-scale results hold. The doc-toolbar Refresh now calls `refreshFromSources(this._resource)`, scoping to that document plus the co-dependents of any source that changed (found via a new `AgentOrchestrator.docsBoundToSource(source)` reverse-edge lookup - reusing the existing graph, no new persistence). A per-pass `IRefreshPass` caches the IN-FLIGHT read PROMISE (not the resolved value) for each source, so a CSV bound by 20 documents is read once per pass even under the concurrent freshness fan-out (concurrent callers await one read rather than racing N identical reads); the same cache dedups remote resolutions per source identity. Single-document paths (source-peek, subtitle, per-doc sync) pass no `IRefreshPass`, so they read fresh exactly as before - the cache is a refresh/agent-run concept only, never a long-lived store that could serve a stale value across passes. **Measured (50 docs / 4 shared CSVs):** full-refresh source reads 248 → 152; a shared CSV read up to 26x → exactly 1x per pass; a one-CSV-changed incremental refresh re-derives only that source's ~13 dependents (54 reads) instead of all 50. **Tier: our-surface, 0 core patches** (`livingDocsService.ts`, `agentOrchestrator.ts` reverse-edge helper, `livingDocEditor.ts` scoped-refresh call, `common/livingDocs.ts` signature). Verified: `perfScale.test.ts` (7 tests) + the fixture generator `test/browser/scaleFixture.ts` + the on-disk `scripts/generate-scale-sample.ts` (50 docs / 4 CSVs, gitignored); the full pre-existing `livingDocsService`/`agentOrchestrator` suites re-run with 0 assertion regressions. Harness timing is marked informational (console-logged, not asserted) per the plan; the count assertions run in CI (they are fast against the mock). Numbers + method in `docs/plans/30-verify/notes.md`.
