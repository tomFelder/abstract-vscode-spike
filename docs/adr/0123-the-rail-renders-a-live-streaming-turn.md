# The rail renders a live streaming turn

**The rail renders a live assistant turn that appends streamed deltas WITHOUT a full re-render; a dedicated `onDidStreamChat` event drives incremental DOM writes, and the streamed text SHOWS the human `reply` prose (not the raw `{"reply":"..."}` envelope) via a pure `extractStreamingReply`. Send becomes a Stop square while busy (Esc also cancels); a failed model call renders an honest error turn with an inline Retry that re-runs the same user message**

Settled to the plan's recommendation. Firing the existing `onDidChange` per token would clear + rebuild the whole ViewPane on every delta (resetting scroll + the composer caret), so the service gained a second, lighter event `onDidStreamChat(URI)` that carries the in-between deltas; `onDidChange` still fires once at busy-on and once at busy-off. The service exposes the in-flight turn via `getStreamingChat(resource)` (`{ text, steps }`); `reviewRailView` keeps DOM handles to the live turn and, on each `onDidStreamChat`, writes the streamed text + refreshes the tool-step card in place, autoscrolling only when the user is already pinned to the bottom (a scroll-up to read history is respected). The first delta does one full re-render to swap the pulse "Thinking" state for the caret form; every later delta is a cheap text write. **Prose, not JSON:** the model reply is a JSON envelope, so a new pure `extractStreamingReply(rawPartial)` in `common/livingDocMarkdown.ts` progressively reads the `reply` string value out of the partial envelope (unescaping `\" \\ \n`, `''` until it starts, plain-text passthrough for a non-envelope reply); the service accumulates the RAW text for the unchanged end-of-stream `parseChatResponse` but sets `streaming.text` (and therefore the salvage on cancel) to the extracted prose. **Stop/Retry:** the composer send button becomes a red Stop square while `isChatBusy` (Esc in the composer also cancels), wired to `cancelChat`; a genuine model error (not a cancel) records an assistant turn with a new `IChatMessage.failed` flag + copy "The model call failed.", which the rail renders as an amber error card with a **Retry** button calling the new `retryChat(resource)` - it drops the failed turn and re-runs the SAME user message (no duplicate user turn), a no-op after a successful turn. `sendChatMessage` was refactored into `sendChatMessage` + `retryChat` + a shared `_deliverChatReply`; tool steps stream via an `onStep` callback threaded into `_chatRespond`/`_chatRespondMulti`. **Tier: our-surface** (service + rail + one `common/` helper; 0 core patches). Verified: 6 pure `extractStreamingReply` tests (partial/closed/escapes/not-started/plain-text/trailing-backslash) + 2 service tests (a failed call records a `failed` turn and `retryChat` replaces it re-running the same message; retry is a no-op after success); and ONE required live in-app pass (web :9080 + mock SSE proxy :8090) captured under `docs/plans/27-verify/` - words stream as clean prose < 1s after send with a blinking caret, the Stop square halts and keeps the salvaged prose under a muted STOPPED tag, and a killed-upstream send shows the Retry error turn.
