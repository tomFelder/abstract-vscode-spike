# List edits anchor at the list-item boundary

**A chat edit to one list item is anchored and applied at the `<li>` boundary via one shared, pure helper family in `common/livingDocMarkdown.ts` (`listItems` / `scopeBlockEdit` / `applyBlockEdit`); approve splices only the matched item's range instead of replacing the whole block**

The known destructive bug (decision 68): a bulleted/numbered list with no blank lines between items parses as a SINGLE block (`parseLivingDoc` splits blocks on blank lines), so its `text` is the whole list. A chat edit that targeted one item stored `oldText = best.text` (the WHOLE list) with an item-scoped `newText`, and `approve` did `block.text = change.newText` - so approving silently deleted every sibling item. Settled to the plan's recommended fix shape (anchor + replace at the list-item node boundary, treating each `li`'s text as its own searchable unit). Chosen implementation: three pure helpers in `common/` - `listItems(blockText)` (per-line item ranges; `[]` for prose), `scopeBlockEdit(blockText, quote)` (narrows a single-item quote to that item's exact slice, else the whole block for prose or a whole-list quote), and `applyBlockEdit(blockText, oldText, newText)` (whole-block replace when `oldText` is the block, else splice `newText` over the matched item's range; **fail-soft** - a scoped anchor that no longer matches leaves the block unchanged rather than wholesale-replacing, which is the exact data loss guarded against). `_queueChatEdit` now scores candidate blocks against the targeted item (so a long list still selects) and stores the SCOPED `oldText`; the wholly-bound skip is relaxed to a **per-item bind guard** so a plain item beside a bound-figure sibling is editable while the bound item itself is never touched (extractBindLinks on the scoped range). `approve` routes through `applyBlockEdit` (still the one approve path - no new apply route). `buildPmDecorationSpec` scopes the anchor + word-diff to the same `<li>` (defence-in-depth: a whole-block `oldText` no longer draws the siblings as deletions). **Tier: our-surface** (two `common/` modules + the service; 0 core patches). Red-then-green proven: 3 failing tests at both named layers before the fix, all green after - 13 new unit tests (8 pure markdown helper incl. ordered/nested/figure-atom/fail-soft, 2 decoration anchoring, 3 service E2E incl. the 4-item data-loss repro, a bound-figure sibling preserved, and a bound item skipped).
