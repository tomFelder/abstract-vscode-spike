# Silence the cold-launch activation noise

**Kill the cold-launch noise via product config-defaults; one minimal core patch silences dev-only built-in activation toasts**

Iter 2 removes the cold-launch IDE/Copilot noise Tom flagged. Four are real settings, set as product defaults (additive, 0 core patches): `security.workspace.trust.enabled:false` (no Restricted-Mode banner — the product trusts its own workspaces), `workbench.welcomePage.experimentalOnboarding:false` (no "Welcome to VS Code / Sign in to use Copilot" modal + no "Make It Yours" walkthrough — both are onboarding steps gated by this flag, `startupPage.ts:245`), `workbench.startupEditor:'none'` (no welcome page), `chat.disableAIFeatures:true` (hides the built-in **GitHub Copilot** chrome — the title-bar Sign-In button + Copilot status — which is safe because the product has its OWN chat in the Review rail, a separate livingDocs contribution that talks to the localhost proxy, untouched by this flag), and `window.title:'${activeEditorShort}'` (the title/command-center shows just the document name, not `${rootName} [remote]`). The one residual — the **"Activating extension 'vscode.X' failed: Not Found"** error toasts — has no setting: `mainThreadExtensionService.$onExtensionActivationError` (`:102`) only toasts when `isDev` (`!isBuilt`), so these are a **dev-build-only** artifact (a built product just `console.error`s) from built-in `vscode.*` extensions this slim build doesn't ship. Since the spike is always run as a dev build and Tom sees them at cold launch, a **minimal, fail-soft core patch** logs built-in activation failures instead of toasting them (`isDev && !extensionId.startsWith('vscode.')`); user/third-party extension errors still toast in dev.
