# The History tab is a truthful version timeline

**The History tab is a truthful per-document version timeline built entirely from the active document's lock - the fabricated v14/v13 sample is deleted; a manual "Save version" and a per-version "Restore" route through the existing service paths**

Settled to the plan's recommendation. The static comp `sample` array (v14/v13/v12/v11, "just now · Tom") is gone; `historyHtml(snapshots, audit, docTitle?, fromTemplate?, now?)` renders REAL data: the header derives from the live document title (`VERSION HISTORY · <TITLE>`), then a newest-first timeline interleaving the real snapshots (`getSnapshots(resource)` - restorable version rows with a via glyph, an amber `SNAPSHOT` badge for `publish`, a relative time, and a quiet `Restore`) with the real audit entries recorded since each (`getLock(resource).audit` - change rows: verb + block + via + time, a `via: 'restore'` entry reading `Restored`). A synthetic `Current version` head carries the `CURRENT` badge (the live state, no Restore); the template-origin row (plan 28 iter 3) stays at the base. Empty state is one calm line (`No versions yet - changes you approve will appear here.`); no document open shows `Open a Living Document to see its version history.`. The display caps at the 20 most recent rows with a mono `N earlier entries` line (the lock keeps the full record - no silent truncation). `Restore` confirms via the platform `IDialogService` (`Replaces the current body. Pending changes will be rejected. This is recorded in the audit trail.`) then calls `restoreSnapshot` - the ONE approve path from iter 2 (rejectAll → persist → audit `via: restore` → recompute freshness); no bypass write. A manual `Save version` prompts via `IQuickInputService` and calls `saveSnapshot(..., 'manual')`. **Deviation (logged):** the pure render was extracted from `reviewRailView.ts` into a new sibling pure module `browser/historyRender.ts` (mirroring `livingDocRender.ts`/`treeRail.ts`) so it is unit-testable without the `ViewPane` module graph; the plan said "rewrite `historyHtml` in `reviewRailView.ts`" but the behaviour and call site are unchanged (the view imports it). Relative times avoid the literal token `just now` (they read `moments ago`/`Nm ago`/`Nh ago`/`Nd ago`/ISO date) so the fabricated-string grep gate stays unambiguous. **Tier: our-surface, 0 core patches.** Verified: 8 `historyRender` unit tests (real snapshots+audit, no sample; Restore wired to the snapshot id; publish SNAPSHOT badge + CURRENT head; truthful empty state; no-doc prompt; restore reads `Restored`; cap-at-20 names the remainder; template origin kept) - 19 assertions, run via an esbuild bundle of the pure module (the sandbox lacks the gulp/mocha toolchain; the suite runs unchanged in CI). Evidence under `docs/plans/26-verify/` is a render-preview of the actual `historyHtml` output plus the unit suites; a live in-app pass on `:8080` was blocked by the sandbox's pruned `node_modules` (no `@vscode/test-web`/`electron`/`gulp`) and did not run - see `iter3-4-README.md`.
