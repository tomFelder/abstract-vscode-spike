# Docx and PDF export behind the reconcile gate

**Export unstubs docx and adds PDF, both behind the existing before-export reconcile gate. docx conversion runs in the node/proxy layer via a zero-dependency pure-JS OOXML writer (`scripts/lwd-docx.js`) exposed as `POST /export/docx`; PDF renders the existing self-contained HTML export through the desktop build's Electron print-to-PDF; gdoc/gsheet/xlsx stay honest "SOON" rows**

Settled to doc 22 §3's recommendation. **docx:** the renderer's resolved export Markdown (bind values already inlined as plain text, exactly like the Markdown export) is POSTed with an image-src->data-URI map to the proxy, which returns a `.docx` mapped to Word's BUILT-IN styles (Title/Heading 1-6/Normal/List Bullet/List Number/Table Grid/Quote/Hyperlink) so the receiving org can restyle - no Abstract chrome, dots or diff UI. A zero-dependency writer (hand-rolled WordprocessingML + a store-method ZIP with CRC32) was chosen over `html-to-docx`/`docx` npm libs to avoid adding a heavy dependency to the fork's build and to keep the writer unit-testable on the pure-node path (macOS `textutil` and `unzip -t` confirm the output is a valid, readable OOXML package). Conversion lives in the proxy (not the renderer) to co-locate all format conversion with the sibling docx IMPORT (mammoth, A1) and xlsx/PDF-source extraction (A3); the honest cost is that docx export needs the local proxy running, which is surfaced plainly (never a broken button, plan 33 L8). **PDF:** print-to-PDF is inherently a main-process capability, so `printToPDF(html)` is added to `INativeHostService` (an offscreen hidden `BrowserWindow` loads the HTML via a data URL and calls Electron's `webContents.printToPDF`); the browser-layer service reaches it through a desktop-only command (`_livingDocs.printToPDF`, registered in a new `electron-browser/livingDocsPdf.contribution`) so it carries no desktop dependency and PDF is honestly absent on the web dev harness rather than crashing. **The before-export gate is reused unchanged** for both formats (a failed grader blocks without `force` and, with "Export anyway", proceeds and audits the override `via:override`). Exports write beside the document like the HTML/Markdown exports; no fabricated hosting. **Tier: 1 core patch** (the `printToPDF` native-host method + its `electron-main` implementation + a `TestNativeHostService` stub + one desktop-barrel import line - minimal, fail-soft, logged in [plans/03-merge-tax-ledger.md](../plans/03-merge-tax-ledger.md)). Verified: pure-node writer test (`scripts/test/lwd-docx.test.js` - built-in styles, inlined values, nested lists, GFM table, hyperlink, embedded image, no `bind:`/provenance chrome) + a live proxy-route smoke (`curl` -> valid `.docx`) + 4 service tests (docx posts resolved Markdown and writes the `.docx`; docx honours the gate + audits the override; PDF hands the HTML to the print command and writes the `.pdf`; PDF is a no-op on the web harness) + the present-modal render test updated (html/markdown/pdf/docx selectable, gdoc/gsheet/xlsx still "SOON").
