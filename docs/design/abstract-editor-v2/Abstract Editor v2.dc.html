Each pin above maps to an entry below. Tokens are the plan-20 Part-B set (verbatim). "Code surface" names the file/contribution to touch; "Tier" follows the merge-tax discipline — our-surface = livingDocs contribution / livingDocRender webview / service; core = shared workbench (log in 03-merge-tax-ledger.md).
1Elevation model — white editor over darker chrome
The app frame is no longer flat. Chrome (window bg) is #EDEFF3 — a step darker than hairline — and the three work panels float on it with 12px gaps: tree rail + right rail on #FBFCFD, editor on paper #FFFFFF. Radius 14 (cards), border line #E9EAEE. Shadows: rails 0 8px 28px -14px rgba(20,22,28,.22); editor (top of stack) 0 12px 36px -16px rgba(20,22,28,.26), both + e1. The white paper is the visual focus — the Obsidian trick, in Abstract's light palette. Monaco note: keep .monaco-editor-background opaque #FFFFFF (never transparent).
Code: workbench layout CSS + livingDocRender shell  ·  Tier: 1 small core CSS seam (part backgrounds/margins) — log it
2Rail toggles live in the header
Two 28px icon buttons at the header's far left / far right collapse the tree rail and right rail (Obsidian's pattern — never a floating chevron mid-editor). Icons: panel glyph with the filled half indicating which side. Keybindings ⌘\ and ⌘⇧\. Collapse animates width→0 + fade over 150ms ease; state persists per-workspace (storage service). When the right rail is collapsed but a proposal is pending, the Review badge count moves onto the toggle button (8px amber dot) so trust-grammar force-open is no longer needed.
Code: livingDocRender top bar + rail contributions (visibility commands exist)  ·  Tier: our-surface
3Icon-nav sits on chrome, not in a panel
76px labeled nav (plan-25 build) keeps its items but loses its panel background — items sit directly on the #EDEFF3 chrome. Active item = 60px white chip, radius 10, e1 shadow, glyph + label accent-hover #4650B8. Idle = muted #868B95, hover slate. 18px stroke glyphs, 10px/500 labels. Settings pinned bottom.
Code: labeled-nav contribution (plan 25) — CSS only  ·  Tier: our-surface
4Tree rail — floating panel, 3 tabs + ＋
264px floating card. 38px tab strip: Files · Context · Outline (Search folds into Files as type-to-filter — 3 tabs read calmer than 4). Active tab = white chip + e1. A quiet ＋ (new document) sits right of the tabs. The whole rail scrolls as one; SOURCES group keeps its mono UPPER label (10px/.12em/faint).
Code: tree-rail ViewPane  ·  Tier: our-surface
5Collapsible tree — status at a glance
Folder rows: 28px, chevron (9px, rotates 90°) + 12.5/600 name + mono doc-count right-aligned. Doc rows: 30px, radius 8, 7px status dot (ok = synced · attention = changes waiting · #D5D8DE = plain) + name + right meta: LWD chip for living docs, amber count pill for docs with pending approvals. Selected row = accent-tint #F4F5FD bg + #E0E5FB border, text accent-ink. Children indent 14px. Twist animates 150ms.
Code: tree-rail ViewPane (VS Code tree widget, restyled)  ·  Tier: our-surface
6Full right-click menu on documents
Context menu (toggle the tweak to see it): 208px popover, radius 12, popover shadow, 6px padding, 30px rows, hairline dividers. Groups: Open / Open to the right · Rename / Duplicate / Move to… · Bind sources… / View history / Present · Delete (removed-ink #B5514B, hover bg #FBEEEE). "Open to the right" is the ONE sanctioned split (side-by-side reference reading) — it may never leave a blank group: closing the last editor in a group closes the group. Delete confirms; Rename is inline in the tree.
Code: tree-rail ViewPane + menu service (native ContextMenuService, restyled)  ·  Tier: our-surface
7Tabbed working surface (product tabs, not IDE tabs)
40px strip on #F3F4F7 inside the editor card. Our own tab row (VS Code's tab strip stays disabled via showTabs:'none'): active tab = white, radius 9 9 0 0, 1px border merging into the toolbar edge, 12.5/600 + status dot + quiet ×; idle tabs text-only, hover #ECEDF1. Sources (metrics.csv) open as tabs too — same surface, ⊞ mono glyph — replacing nothing about the bottom source-drawer (pin 10). No drag-to-split, no reorder-into-groups; overflow scrolls horizontally. Middle-click closes. Cap visible tabs ~8, then overflow menu.
Code: livingDocRender shell (own DOM above the webview) or a thin editor-group header replacement  ·  Tier: our-surface, possibly 1 core seam if group header is replaced
8Toolbar unchanged — plus Properties entry
The pared 44px toolbar ships as-is (borderless Paragraph ▾, B/I, list/ordered/quote, all via LWDPM.cmd; no underline). Right side gains one control: Properties (list glyph + label), which toggles pin 12. Order: ✦ Ask AI · Properties · ● Saved · v14. Nothing else is added — the calm-toolbar rule from the v4 loop holds.
Code: livingDocRender .etoolbar  ·  Tier: our-surface
9Numbered gutter — the annotation rail (revises plan-20 §C2)
Design change, Tom-approved: the 30px dot-only gutter becomes a 70px line-numbered gutter (Obsidian learning). Numbers: JetBrains Mono 11px, right-aligned, 22px from the text edge, idle #C6CAD2 (quieter than faint — invisible until useful). Numbering follows the D1 wrap rule: one number per Markdown line/block; wrapped visual rows show blank gutter. Provenance rides the numbers: a bound line's number turns accent #5B6DC4/600 + 9px dot to its left; a pending-edit block gets an attention number + 3px vertical bar spanning its rows. Hover a marked number → source-peek drawer. Numbers give chat/review a shared address ("line 6") — use them in proposal cards. Implement as a PM gutter decoration column (flex:none, left of the 720px doc column; prose never shifts).
Code: PM decorations in livingDocRender bundle (replaces margin-dot deco)  ·  Tier: our-surface  ·  update plan-20 §C2 + decision log
10Bound figures + source drawer (unchanged)
Bound figures stay per spec: non-editable PM atom, text #4650B8/500, 2px dotted underline #9AA2E0, round-trips to [label](bind:key). Click → fixed bottom source drawer (52–54%, z-25, referenced row in accent-tint) — never a second editor group. The drawer and the metrics.csv tab coexist: drawer = quick provenance peek; tab = working in the source.
Code: shipped — no change  ·  Tier: our-surface
11Inline proposal — now addressed by line
Word-diff in the document (add #E9F6EE/#2C8159, remove #FBEEEE strike #CF5A53) + attention widget with mono tag, one-line rationale, Approve (accent fill) / Reject (ghost). New: the widget and the rail card both cite the gutter address ("Line 6") — the number rail (pin 9) makes changes referenceable in conversation.
Code: PM widget decoration (shipped) + address string in proposal model  ·  Tier: our-surface
12Properties panel — frontmatter without the YAML
284px inset panel inside the editor card (right edge, rail bg, hairline left border) — Obsidian's Properties, Abstract-calm. Reads/writes the doc's YAML frontmatter + lock.json: TITLE · CREATED/UPDATED (mono) · STATUS chip · TAGS (accent-tint chips + ＋) · BOUND SOURCES (rows with bind counts; click → drawer) · AGENT POLICY (plain-language, per-doc "ask me first"). Footer: "Edit raw YAML →" opens the raw view — plain front door, pro back door. Toggled from the toolbar (pin 8); state per-doc. Field labels: mono 9.5px UPPER .12em faint. The 720px reading column re-centers in the remaining width when open.
Code: livingDocRender shell panel + parseLivingDoc frontmatter API  ·  Tier: our-surface
13Right rail — floating, same 3 tabs
392px floating card, Chat · Review (amber count badge) · History. Tab treatment matches the tree rail (white chip + e1 active). Content per plan-20 §C6 — no structural change beyond the float + the line-address references (pin 11).
Code: right-rail contribution CSS  ·  Tier: our-surface
